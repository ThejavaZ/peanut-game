## 1. Purpose of this document

This roadmap defines **what v1 is**, **what is already done**, **the order of work**, and **how we know a milestone is finished**.

It is a living document. When a decision changes the scope, the change is recorded here first, then implemented. Anything not listed in section 9 (Out of scope) is not part of v1.

**Design rule:** the game must never feel unfair because of missing information, but the player must never fully control Peanut's fate either.

- [x] Care actions: feed, water, clean, play, sleep — each with cooldown and visible effect.
- [x] Naming screen with input validation and adoption flow.

- [x] Unit tests for the engine and save validation (`bun test`).

**Exit criteria:** adopt → name → care for several in-game days; stats decay and recover; reloading restores the exact session. _(verified: decay, cooldowns, pause, reload and continue flow)_

- [x] "Adopt another hamster" flow back into M1.

### M3 — Minigames

**Goal:** give the player something to *do* beyond bars, with concrete rewards.

- [x] Minigame shell: pauses the clock, shared reward contract, skip/exit.
- [x] Hamster Wheel — timing/reflex, rewards happiness.
- [x] Find the Seeds — spot-the-object under a time limit, rewards food.
- [x] Tiny Maze — small grid, keyboard + touch, clears care cooldowns.
- [x] Nap Time — advances time, small health recovery.
- [x] Rewards tuned so minigames help but do not make needs irrelevant. _(hard caps, a 60 s gap between minigames, and a test proving no minigame can feed, water or clean)_

> **Scope note:** *"food/items"* and *"items/upgrades"* from the original draft
> are honoured as **needs and cooldown wipes** — v1 has no inventory (§9), so
> rewards map onto the five bars instead of inventing an economy.

**Exit criteria:** each minigame is playable with mouse and keyboard, applies rewards correctly, and never soft-locks the run.

**All M3 items complete (2026-11-20).** Four minigames — nap, wheel, maze and
seeds — share one shell, one reward contract and one gap; every criterion above
is met and covered by tests.

**Goal:** the ideas that did not fit v1, planned before any of it exists.

**One card for the whole milestone — [#43](https://github.com/ThejavaZ/peanut-game/issues/43)** —

This section is the plan; the card is the checklist.

**Order** (dependencies in brackets):

1. Video game culture skins — cheap win, zero risk, the pipeline already exists
2. Dark mode — the theme layer the next step needs
3. Real time after 3 AM turns the game dark `[needs dark mode]`
4. Deaths caused by the player's own actions
5. Creepypasta endings `[needs action deaths]`
6. Direct interaction and petting
7. Disease system — the largest change, alone in its sprint: new state, stages,
   treatments, **schema v7** and an eighth cause of death

**Decisions taken before the first commit:**

- **Localization is out of scope again** (issue #37 closed): the game ships in
  English, and every string stays in one language. Recorded in §9 below.
- **Diseases can kill** → an eighth cause of death, following the same rule as
  the other seven: a warning first.
- **Death by the player's own action arrives as an explicit choice**, never as
  hidden chance, so the M2 invariant — *no death without a prior warning or an
  explicit choice* — keeps holding.
- **One schema change per sprint, never two**: the chained migration works
  because each sprint adds exactly one step.

**Exit criteria:** every box on #43 is checked, the suite never drops below the
197 tests it starts with, and `docs/roadmap/v1.md` and `docs/GAMEPLAY.md` are

## 5. Technical decisions (ADR-lite)

1. **Engine decoupled from React.** Needs, clock, events and death live in `src/game/` as pure functions. React only renders state and dispatches actions. Changing hunger math must not touch five components.
2. **State via `useReducer` + a small context.** No Redux or Zustand until proven necessary.
3. **Screens as a state machine, not routes.** One URL, no router, no 404s on GitHub Pages.
4. **Versioned persistence.** `localStorage` payload carries `schemaVersion`; save on key actions and on an interval — never every tick.
5. **Audio with Web Audio API.** Synthesized SFX first; no heavy assets in the first build.
6. **DOM + CSS rendering.** Pixel art via CSS scaling; no canvas engine unless a minigame truly needs it.
7. **Time is derived from real elapsed time.** Pause when the tab is hidden; cap offline decay.
8. **Deployment through GitHub Actions.** `base: '/peanut-game/'`, build artifact published to Pages.

## 8. Workflow

### Local setup

```bash
bun install
bun run dev      # development server
bun run test     # engine, save and sprite tests
bun run lint
bun run build
```

### How to pick up work

1. Choose an unchecked item from the current milestone (M2).
2. Open an issue with the milestone label and a one-line acceptance criterion.
3. Create a branch: `feat/...`, `fix/...`, `docs/...` or `chore/...`.
4. Keep the change small and update this roadmap if the scope changes.
5. Open a PR; `main` must always be deployable.

- **Commits:** Conventional Commits (`feat: add needs decay`, `docs: update roadmap`).
- **Definition of done:** item checked in this roadmap, tests cover the logic, `bun run test`, `bun run lint` and `bun run build` pass, and docs are updated when behaviour changes.
- **No new dependencies** without a reason recorded in the PR.

## 9. Out of scope for v1

- Backend, accounts, authentication, cloud saves.
- Multiplayer or leaderboards.
- Shop, payments or monetization.
- Open world, breeding, genetics, AI.
- Hundreds of events or complex animation systems.
- Localization beyond English. _(back on this list on 2026-11-21: dropped by decision — issue #37 closed; translating the whole codebase is work we choose not to take on)_
- The entire M5 expansion (#30–#37) until v1.0.0 has shipped.

Post-v1 ideas: **Peanut Legacy** (references to past hamsters in new runs),
daily challenges, more minigames, unlockable rooms, expanded event packs. The
ones promoted into a milestone are tracked in M5 above; the rest stay here
until someone argues for them.
