## 1. Purpose of this document

This roadmap defines **what v1 is**, **what is already done**, **the order of work**, and **how we know a milestone is finished**.

It is a living document. When a decision changes the scope, the change is recorded here first, then implemented. Anything not listed in section 9 (Out of scope) is not part of v1.

**Design rule:** the game must never feel unfair because of missing information, but the player must never fully control Peanut's fate either.

## 3. Milestones

Each milestone ends with a **working, committable state** on `main`. A milestone is only closed when its exit criteria are met.

### M0 — Foundation

**Goal:** turn the scaffold into a deployable shell with the project's identity.

- [x] Repository, license and proposal.
- [x] Vite + React + TypeScript scaffold.
- [ ] Install Tailwind CSS v4 with the Vite plugin (`@tailwindcss/vite`).
- [ ] Define theme tokens: pastel palette, pixel font, spacing, borders.
- [ ] Replace the Vite demo (`App.tsx`, `App.css`, demo assets) with an app shell.
- [ ] Screen state machine: `menu → naming → game → memorial` (no router needed).
- [ ] Base folders per `ARCHITECTURE.md`: `src/game/`, `src/features/`, `src/components/`.
- [ ] Pixel-art rendering strategy: 320×180 internal viewport, integer scaling, `image-rendering: pixelated`.
- [ ] `vite.config.ts`: `base: '/peanut-game/'` for Pages.
- [ ] GitHub Actions workflow: build + deploy to Pages on push to `main`.
- [ ] Update README with the live demo URL.

**Exit criteria:** a public URL shows the Peanut main menu, `bun run build` passes, no Vite template leftovers.

---

### M1 — Core gameplay

**Goal:** a hamster can be adopted, named, cared for and kept alive by the player.

- [ ] Types: `Hamster`, `Needs`, `GameState`, `CareAction`, `GameScreen`.
- [ ] Pure needs update function: decay per tick, clamping, warning thresholds.
- [ ] Game clock: fixed timestep derived from real elapsed time; pause/resume; handle tab visibility.
- [ ] Offline progression cap (e.g. max 8 h of decay) so returning is punishing but not fatal-by-default.
- [ ] Care actions: feed, water, clean, play, sleep — each with cooldown and visible effect.
- [ ] Naming screen with input validation and adoption flow.
- [ ] Stats HUD with warning states. **Zero is not instant death.**
- [ ] Save/load in `localStorage` with `schemaVersion`; reset option.

**Exit criteria:** adopt → name → care for several in-game days; stats decay and recover; reloading restores the exact session.

---

### M2 — Events & death

**Goal:** every run can end differently, and the ending is remembered.

- [ ] Event model: `id`, `weight`, `cooldown`, `conditions`, `choices`, `effects`.
- [ ] Weighted scheduler with minimum interval and once-per-run flags — never one event per second.
- [ ] Event modal with 1–2 choices and **visible consequences** before choosing.
- [ ] Health degradation rules derived from unmet needs (progressive, readable).
- [ ] `DeathSystem`: evaluate causes by priority, produce an immutable `DeathRecord`.
- [ ] Content targets: **≥ 8 events** and **≥ 6 causes of death**, mixing negligence, absurd and inevitable.
- [ ] Memorial screen: name, age, days survived, meals, play sessions, cause of death, epitaph.
- [ ] Cemetery: persisted history of previous hamsters, browsable.
- [ ] "Adopt another hamster" flow back into M1.

**Exit criteria:** at least three distinct endings are reachable; memorial and cemetery survive a reload; no death happens without a prior warning or an explicit absurd-event choice.

---

### M3 — Minigames

**Goal:** give the player something to *do* beyond bars, with concrete rewards.

- [ ] Minigame shell: pauses the clock, shared reward contract, skip/exit.
- [ ] Hamster Wheel — timing/reflex, rewards happiness.
- [ ] Find the Seeds — spot-the-object under a time limit, rewards food/items.
- [ ] Tiny Maze — small grid, keyboard + touch, rewards items/upgrades.
- [ ] Nap Time — advances time, small health recovery.
- [ ] Rewards tuned so minigames help but do not make needs irrelevant.

**Exit criteria:** each minigame is playable with mouse and keyboard, applies rewards correctly, and never soft-locks the run.

---

### M4 — Polish & release

**Goal:** ship v1.0.0.

- [ ] `AudioService` with Web Audio API synth SFX first, then optional files; mute + volume persisted.
- [ ] Ambient music loop, quiet and adorable.
- [ ] Pixel art: hamster sprites (idle, eat, sleep, play, dead), room background, props.
- [ ] Responsive layout, reduced-motion support, visible focus states.
- [ ] Balance pass: target run length **5–15 minutes**.
- [ ] Docs updated: `GAMEPLAY.md`, `ARCHITECTURE.md`, `ART_AND_AUDIO.md`, `DEVELOPMENT.md`, this roadmap.
- [ ] 3–5 minute code explainer video (engine, events, deaths, persistence).
- [ ] Tag `v1.0.0` + release notes.

**Exit criteria:** the game is live on GitHub Pages and can be played start-to-memorial in one sitting with no console errors.

## 5. Technical decisions (ADR-lite)

1. **Engine decoupled from React.** Needs, clock, events and death live in `src/game/` as pure functions. React only renders state and dispatches actions. Changing hunger math must not touch five components.
2. **State via `useReducer` + a small context.** No Redux or Zustand until proven necessary.
3. **Screens as a state machine, not routes.** One URL, no router, no 404s on GitHub Pages.
4. **Versioned persistence.** `localStorage` payload carries `schemaVersion`; save on key actions and on an interval — never every tick.
5. **Audio with Web Audio API.** Synthesized SFX first; no heavy assets in the first build.
6. **DOM + CSS rendering.** Pixel art via CSS scaling; no canvas engine unless a minigame truly needs it.
7. **Time is derived from real elapsed time.** Pause when the tab is hidden; cap offline decay.
8. **Deployment through GitHub Actions.** `base: '/peanut-game/'`, build artifact published to Pages.

## 6. Open questions

- Exact offline progression cap.

- How much randomness is "funny" before it feels unfair.

## 7. Risks

| Risk                          | Impact | Mitigation                                                  |
| ----------------------------- | ------ | ----------------------------------------------------------- |
| Scope creep                   | High   | Section 9 is a hard boundary; new ideas go to the post-v1 list |
| Art assets take too long      | Medium | Placeholder shapes first; sprites replaced in M4            |
| Balance feels unfair          | High   | Warnings before every avoidable death; playtest early       |
| GitHub Pages base path issues | Medium | Configure `base` in M0 and deploy a dummy build immediately |
| React Compiler / ESLint noise | Low    | Fix lint config in M0, keep `bun run lint` green            |

## 8. Workflow

- **Branches:** `feat/...`, `fix/...`, `docs/...`, `chore/...`.
- **Commits:** Conventional Commits (`feat: add needs decay`, `docs: update roadmap`).
- **Issues:** one issue per checklist item, grouped by milestone M0–M4.
- **PR checklist:** `bun run build` and `bun run lint` pass; no new dependencies without a reason.
- `main` must always be deployable.

---

## 9. Out of scope for v1

- Backend, accounts, authentication, cloud saves.
- Multiplayer or leaderboards.
- Shop, payments or monetization.
- Open world, breeding, genetics, AI.
- Hundreds of events or complex animation systems.
- Localization beyond English.

Post-v1 ideas (not scheduled): **Peanut Legacy** (references to past hamsters in new runs), daily challenges, more minigames, unlockable rooms, expanded event packs.
